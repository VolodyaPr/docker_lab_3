## Вопросы

### 1. Зачем в Ч.1 использовался --link и почему в Compose он не нужен?
* Флаг `--link` - это первый способ связать контейнеры в Docker. Он прописывал IP-адрес и имя связанного контейнера в файл `/etc/hosts` внутри контейнера, чтобы тот мог обращаться к нему по имени. Docker Compose по умолчанию автоматически создает для всех сервисов проекта общую изолированную сеть. Внутри этой сети работает встроенный DNS-сервер Docker. Благодаря ему контейнеры могут обращаться друг к другу просто по имени.

### 2. Чем отличается image от build в Compose?
* `image`: Указывает Docker Compose, что нужно скачать готовый образ из реестра (например Docker Hub) или использовать уже имеющийся локально.

* `build`: Указывает Docker Compose, что образ нужно собрать самостоятельно из исходного кода. Вы указываете путь к папке, где лежит Dockerfile.

### 3. Почему нельзя масштабировать сервис с публикацией фиксированного порта на одном хосте? Перечислите способы обойти это ограничение.
* Сетевой порт на хосте это уникальный ресурс. Операционная система не позволит двум разным процессам одновременно слушать один и тот же порт. Если первая реплика заняла порт 8085, вторая при попытке запуска выдаст ошибку `port is already allocated`.

Способы обойти:

* Динамические порты: Указать в Compose "0:5000". Тогда Docker сам выделит каждой реплике случайный свободный порт на хосте.
* Использовать обратный прокси/Балансировщик: Запустить отдельный контейнер (например, с Nginx, Traefik или HAProxy), который займет порт 8085 и будет распределять входящие запросы между всеми репликами по их внутренним портам.
* Использовать Docker Swarm: В режиме Swarm (он же оркестратор) есть встроенный механизм балансировки, который позволяет публиковать фиксированный порт для всего сервиса, а трафик сам распределяется по всем репликам.
  
### 4. Что делает docker compose down -v и чем отличается от down без -v?
`docker compose down`: Останавливает и удаляет контейнеры и сети, созданные для проекта.

Без флага `-v` данные в томах сохранятся на диске. С флагом `-v` происходит полная очистка то есть удаляется всё, включая базы данных и кэш.

### 5. Как в Compose обеспечивается сетевое имя сервиса для обращения из другого сервиса?
Это обеспечивается за счет встроенного DNS-сервера Docker и пользовательской сети. При запуске `docker compose up` создается новая сеть и все контейнеры сервисов подключаются к этой сети. Имя каждого контейнера в сети совпадает с именем сервиса в `docker-compose.yml`. Когда контейнер `rocketcounter` пытается обратиться к хосту `redis`, Docker перехватывает DNS-запрос через внутренний DNS и возвращает актуальный IP-адрес контейнера `redis`. Поэтому в коде достаточно указать просто `redis` в качестве хоста.
